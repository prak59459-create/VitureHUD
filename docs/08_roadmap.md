# 08. 開発ロードマップ

期間は **個人開発・週10時間前後** を仮定した目安です。実機検証の結果で前後します。

**共通ルール（全Phase）：** 実装はこのリポジトリで行い、PR ごとに GitHub Actions（Linux テスト → iOS ビルド・シミュレータテスト・スナップショット）が通ることを条件にする。実機（AltStore）は週7回までとし、週の成果を Release IPA にまとめて「今回の実機チェックリスト」とともに確認する。

## Phase 0：CI構築＋技術スパイク（承認後すぐ／約1〜2週）

**実機検証は週7回まで**（[13](13_ci_altstore_pipeline.md) §6）のため、スパイクは1つの検証用アプリ（`HUDNavigator` の最初のビルド）に **診断画面としてまとめて入れ**、1回のインストールで S0-1〜S0-8 を一度に確認する。合否と分かったことを `docs/spike_results.md` に記録する。

| ID | 検証内容 | 合格条件 | 不合格時の方針 |
|----|----------|----------|----------------|
| S0-0 | **CI → AltStore 経路**：GitHub Actions で `HUDCore` テスト・iOS ビルド・未署名 IPA 作成 → Release → iPad / iPhone の AltStore でインストール・起動 | 両端末でアプリが起動する | IPA の作り方（Payload 構成、Bundle ID、署名設定）を調整。AltStore 側のエラー内容を記録 |
| S0-1 | **外部ディスプレイ独立表示**：インストールしたアプリから VITURE に端末画面と別の内容を出せるか | グラスに「EXTERNAL」、端末に「MAIN」と別表示される／抜き差しで復帰する | ミラーモードを標準にする |
| S0-2 | **黒背景の透過と視認性**：黒背景＋色・サイズ・太さ違いの文字見本をグラスで見る（室内・屋外） | 推奨最小文字サイズ・推奨色を決定できる | — （結果をテーマ設計に反映） |
| S0-3 | **カメラ＋外部出力の同時動作**、カメラ遅延の目視計測 | 10分連続で動作、発熱状態が `.serious` にならない | 解像度/fps を下げる、カメラモードを端末画面専用にする |
| S0-4 | **権限**：カメラ・位置・マイク・音声認識・モーションの許可ダイアログ（`project.yml` に権限説明を記載） | 各権限ダイアログが表示され取得できる | 説明文・設定を修正 |
| S0-5 | **Core ML モデル**：ビルド時コンパイルしたモデルで推論できるか（CI のシミュレータで先に確認、実機で速度確認） | CI で推論結果が出る／実機で fps を記録 | Vision 内蔵機能（人・犬猫）のみで Phase 4 を構成 |
| S0-6 | **位置情報**：iPad A16（Wi-Fi/Cellular どちらか）での位置・速度・方位の取得状況 | 値と精度を記録 | ナビ検証は iPhone 15 または GPX再生で行う |
| S0-7 | **App Intents**：AltStore で入れたアプリのアクションがショートカットアプリに表示されるか | ショートカットアプリにアクションが出る | Phase 6 で再検討 |
| S0-8 | **日本語音声認識（端末内）・音声合成** | 「黒背景にして」が認識できる／日本語読み上げ | クラウド認識は使わず、手動操作中心 |

**実機の使用回数（Phase 0）：** S0-0 の初回インストール＋修正確認で2〜3回、S0-1〜S0-8 の一括確認で1〜2回。

**Phase 0 の成果物：** CI ワークフロー一式（緑の状態）、スパイク結果レポート、実現可能性一覧の更新、Phase 1 の詳細タスク表。

## Phase 1：HUD基本プロトタイプ（約2〜3週）← VITURE 実機検証

- AppState / AppEnvironment / CommandBus の骨格
- DisplayManager（`.local` / `.mirror` / `.independent`）
- 背景：黒／カメラ、切替、カメラ明るさ・ズーム・起動停止
- HUDパネル（1〜3枚）：時計・バッテリー・テキスト。移動・サイズ変更・透明度
- HUDキャンバスの表示位置オフセット・スケール（グラスの見え方調整）
- レイアウトのJSON保存・復元
- 診断オーバーレイ（fps・温度・電池）・実機テストモード（チェックリスト・JSON書き出し）の土台

**完了条件：** VITURE 装着で、黒背景にパネルが見え、端末の操作で移動・サイズ変更でき、アプリ再起動・グラス再接続で配置が復元される。

## Phase 2：HUDカスタマイズ（約3週）

- 複数パネル・複製・削除・表示順・表示/非表示
- LayoutEngine（グリッドスナップ・端揃え・重なり防止）
- スタイル個別設定（色・フォント・サイズ・太さ・枠・角丸・影・発光・アニメ）
- テーマ7種＋ユーザーテーマ、インポート/エクスポート（JSON）
- プリセット7種＋ユーザープリセット
- 標準ウィジェット（センサー不要のもの：時計・日付・バッテリー・通知枠）

## Phase 3：ナビゲーション（約4週）

- LocationService（位置・速度・方位）＋ **GPX再生モック**
- MapKit：2D/3D、追従、ヘディングアップ/ノースアップ、全画面地図
- 検索：施設名・住所・地図タップ・周辺カテゴリ
- ルート：徒歩/車、複数ルート比較、距離・所要時間・ETA
- RouteProgressEngine：次の曲がり角、残り距離、逸脱→再検索
- 音声案内（GuidancePlanner）：読み上げタイミング・頻度・音量
- HUDウィジェット：ミニマップ・次の曲がり角・速度・ETA・コンパス・GPS状態
- 公共交通は「ETA表示＋Apple マップで開く」

## Phase 4：センサー・AIビジョン（約4週、実験機能）

- MotionService・活動推定・PowerGovernor 本実装
- CameraService のフレーム出力 → DetectionService（Vision 内蔵 → Core ML モデル）
- 検出オーバーレイ（枠・ラベル・信頼度）
- HazardEvaluator（枠の拡大率・画面中央への接近）→ 警告（表示・音・強度）
- 「実験機能・安全装置ではない」表示と初回同意

## Phase 5：AIアシスタント（約3週）

- SpeechInputService（押して話す）
- IntentParser（日本語コマンド辞書）→ AppCommand
- 音声での目的地検索・ナビ開始・HUD操作
- AssistantProvider：ローカル（定型応答）／クラウド（ユーザーAPIキー・同意制）
- オフライン時の切替

## Phase 6：追加機能（約4週）

- 天気・空気質（Open-Meteo、出典・更新時刻表示）
- 通知・警告の個別設定（AlertPolicy）
- 履歴（オプトイン）・統計・グラフ
- 設定一式のエクスポート/インポート（iCloud Drive 経由）
- App Intents（S0-7 が合格した場合）
- **Xcode移行の判断**（CloudKit・WeatherKit・Google Maps・ウィジェット・Watch を入れるか）

## Phase 7：最適化・実機検証（約2〜3週）

- iPad A16 / iPhone 15 / VITURE 接続での総合テスト（[09_test_plan.md](09_test_plan.md)）
- 発熱・電池・fps・GPS精度・カメラ遅延・視認性の計測と PowerGovernor の調整
- 長時間（60分）安定性テスト
