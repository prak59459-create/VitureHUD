# 09. テスト計画

## 1. 前提：Swift Playgrounds ではテストターゲットが使えない可能性

XCTest / Swift Testing のテストターゲットを Swift Playgrounds の App プロジェクトで使える見込みは低い【未確認】。そこで3層で検証する。

| 層 | 対象 | 方法 |
|----|------|------|
| ① ロジックテスト | `Domain/`（LayoutEngine, RouteProgressEngine, GuidancePlanner, HazardEvaluator, IntentParser, AlertPolicy, Codable往復） | **アプリ内セルフテスト**（`Diagnostics/SelfTestRunner`）。設定→詳細→セルフテストで実行し、合否を一覧表示。将来 `Domain/` を Swift Package に切り出せば、GitHub Actions 等で `swift test` も可能 |
| ② シミュレーション | センサー・ナビ・検出 | **モック・再生**：GPX再生（位置）、記録済みモーション再生、静止画/録画動画を検出パイプラインへ入力 |
| ③ 実機テスト | 外部ディスプレイ、カメラ、発熱、視認性、屋外GPS | チェックリスト＋計測値の記録（本書 §4） |

## 2. ロジックテスト例

| ID | 対象 | ケース |
|----|------|--------|
| T-LAY-01 | NormalizedRect | 1080p / iPad / iPhone のキャンバスで同じ相対位置に描画される |
| T-LAY-02 | LayoutEngine | グリッドスナップ、画面外にはみ出さない、重なり解消 |
| T-LAY-03 | HUDLayout Codable | 保存→読込で完全一致、旧バージョンのJSONも読める |
| T-NAV-01 | RouteProgressEngine | 経路上の点→残り距離・次の曲がり角が正しい |
| T-NAV-02 | 逸脱検知 | 経路から30m以上・10秒以上離れたら再検索要求（閾値は設定値） |
| T-NAV-03 | GuidancePlanner | 「200m先」「50m先」「まもなく」を各1回だけ読む／頻度設定の反映 |
| T-VIS-01 | HazardEvaluator | 枠が一定時間で急拡大＋画面中央 → 危険度「高」／遠方の静止物 → 「なし」 |
| T-AST-01 | IntentParser | 「黒背景に変更して」→ `.setBackground(.black)`、「ミニマルモードにして」→ `.applyPreset("ミニマル")`、表記ゆれ（くろはいけい/黒い背景） |
| T-ALT-01 | AlertPolicy | 危険警告はナビ案内より優先、同種の通知は抑制間隔内で重複しない |
| T-PWR-01 | PowerGovernor | thermalState / 電池残量に応じた品質レベル |

## 3. シミュレーション

- **GPX再生**：自宅周辺の徒歩ルートを一度記録（iPhone）→ iPad で再生しナビを検証（iPad Wi-Fi モデルでもナビの開発ができる）。
- **検出の再生**：歩道の動画を `AVAssetReader` で読み、検出パイプラインに流す → 誤検知・検知漏れの確認、fps計測。
- **外部ディスプレイなしの確認**：端末画面上に「1920×1080 プレビュー枠」を表示するデバッグ機能。

## 4. 実機テスト

### 4-1. 外部ディスプレイ（VITURE）

| ID | 手順 | 期待結果 |
|----|------|----------|
| T-DSP-01 | アプリ起動後にグラス接続 | 出力モードが自動切替、HUDが表示 |
| T-DSP-02 | 表示中にケーブルを抜く→差す | クラッシュせず、配置・モードが復元 |
| T-DSP-03 | 端末の回転 | グラス側HUDは横長のまま崩れない |
| T-DSP-04 | 表示位置オフセット・スケール調整 | 視野の端でも文字が読める位置に調整できる |
| T-DSP-05 | 30分連続表示 | 表示の乱れ・メモリ増加なし |

### 4-2. 視認性（S0-2 で基準作成、各Phaseで確認）

- 室内（照明あり）／屋外（日陰）／屋外（晴天）で、文字サイズ（px）×色×太さの見本を読めるか
- HUDが視界を遮る割合（パネル総面積 / 画面面積）を記録 → 歩行中プリセットは上限を設ける（初期値 15%）

### 4-3. カメラ

| ID | 内容 | 計測方法 |
|----|------|----------|
| T-CAM-01 | 起動・停止・背景切替 | 10回繰り返して異常なし |
| T-CAM-02 | 遅延 | 画面にミリ秒表示のストップウォッチを映し、別カメラで「実物」と「表示」を同時撮影して差を読む |
| T-CAM-03 | fps | 診断オーバーレイの値を記録 |

### 4-4. ナビ・センサー（屋外、iPhone 15 推奨）

- 既知ルート（約1km）を歩き、案内のタイミング、残り距離の誤差、到着判定を記録
- 速度表示と実際の歩行速度の比較、コンパスの方位ずれ（既知の方角と比較）

### 4-5. 性能・電力

| 指標 | 計測 | 目標（初期値） |
|------|------|----------------|
| HUD描画fps | 診断オーバーレイ | 60fps（カメラ無し）／30fps以上（カメラ有り） |
| 推論fps | 同上 | 5〜10fps |
| 発熱 | `thermalState` の推移を1分ごとに記録 | 30分で `.serious` に達しない |
| 電池消費 | 開始・終了時の残量 | 測定し記録（目標は Phase 7 で設定） |
| メモリ | 診断オーバーレイ | 長時間で増加し続けない |

### 4-6. 安全・プライバシー

- カメラ使用中インジケーターが常に表示される
- 履歴保存がOFFのとき何も保存されない／全削除で消える
- 通信ログに、天気・クラウドAI以外の通信がない
- 危険検知の初回利用時に「実験機能」の説明と同意が表示される

## 5. 各Phaseの完了判定

Phase ごとに「ロジックテスト全合格＋該当実機チェックリスト実施」を完了条件とし、結果を `docs/test_reports/phaseN.md` に残す。
